0ver.1 からの変更と、その理由

「飛ばす・戻る」「区間の自由設定」「最大出目の可変」を入れるにあたり、ver.1 のモデルでは4か所が構造的に成立しなくなった。その解消のための変更。

ver.1 の作り何が壊れるかver.2 での対応
現在位置 ＝ 着地駅の OrderNo 最大値 戻ると成立しない。10番地から8番地へ戻っても、最大値は10のままで現在位置が更新されない Turn（手番）テーブルを新設し、最後に完了したターンの終了位置を現在位置とする。時系列で決まるので前後どちらへ動いてもよい
UNIQUE(MissionSetId, StationId) 再訪ができない。戻る・ジャンプでは同じ駅を必ず通り直すため、2回目の記録で制約違反になる 一意制約を外し、Visit を「訪問イベントを積む」テーブルに変更。踏破率は DISTINCT で数える
CHECK (DiceValue BETWEEN 1 AND 6) 最大出目を7以上にすると制約違反 1〜9に緩和。ルームごとの上限は MissionSet.DiceMax に持ち、アプリ側で乱数の範囲を決める
区間の概念がない 始点はコースの先頭、終端はコースの末尾に固定。一部区間・逆走ができない MissionSet に StartStationId / GoalStationId を追加。進む向きは両者の前後関係から導出する
出目が着地時にしか保存されない （ver.1 からの積み残し）移動中にアプリが落ちると着地駅が復元できない 副次的に解消。Turn はサイコロを振った時点で INSERT されるため、出目と行き先が残る

6導出値（テーブルを持たない値）

ID値定義ver.1 からの変更
DV-01現在位置 TurnNo が最大の完了済みターンの EndStationId。完了ターンが0件なら MissionSet.StartStationId 変更。「OrderNo 最大の着地駅」では戻ったときに成立しない
DV-02進む向き Start.OrderNo < Goal.OrderNo ? +1 : -1 NEW
DV-03区間内の駅 OrderNo が Start と Goal の間（両端含む）にある駅。並び順は OrderNo × 向き の昇順 NEW
DV-04着地駅 現在位置 + 向き × 出目。ゴール側でクランプ 向きとクランプを考慮
DV-05効果適用後の終了位置 進む/戻るは着地駅から加減してクランプ、ジャンプは指定駅、それ以外は着地駅のまま NEW
DV-06踏破率 COUNT(DISTINCT Visit.StationId) / 区間内の駅数 変更。再訪を重複して数えないため DISTINCT が必須。分母も全駅から区間内へ
DV-07ミッション達成率 MissionDone=1 のターン数 / SelectedMissionId が入ったターン数 集計元が Visit から Turn へ
DV-08クリア判定 DV-01 が GoalStationId と一致 コース終端からルームのゴールへ
DV-09進行中ターン EndStationId IS NULL の Turn（最大1行） NEW ver.1 では端末にしか無かった情報がサーバーに乗った
DV-10既出ミッション そのルームで SelectedMissionId に既に使われたミッション。再訪時の候補から除外する（R-14） NEW

7主要SQL

全文は 06_schema.sql §10。ここでは要点のみ。@Dir は進む向き（+1 / -1）。

7.1ルーム設定と進む向きの取得

SELECT @CourseId = ms.CourseId, @DiceMax = ms.DiceMax,
       @StartOrder = ss.OrderNo, @GoalOrder = gs.OrderNo
FROM dbo.MissionSet ms
JOIN dbo.Station ss ON ss.StationId = ms.StartStationId
JOIN dbo.Station gs ON gs.StationId = ms.GoalStationId
WHERE ms.MissionSetId = @MissionSetId;

DECLARE @Dir INT = CASE WHEN @GoalOrder > @StartOrder THEN 1 ELSE -1 END;

7.2現在位置（DV-01）

SELECT TOP (1) s.StationId, s.Name, s.OrderNo
FROM dbo.Turn t
JOIN dbo.Station s ON s.StationId = t.EndStationId
WHERE t.MissionSetId = @MissionSetId AND t.EndStationId IS NOT NULL
ORDER BY t.TurnNo DESC;
-- 0件なら MissionSet.StartStationId が現在位置

7.3着地駅と通り道駅（DV-04）

DECLARE @Raw INT = @CurrentOrder + @Dir * @Dice;
DECLARE @TargetOrder INT =
    CASE WHEN @Dir = 1 THEN (CASE WHEN @Raw > @GoalOrder THEN @GoalOrder ELSE @Raw END)
         ELSE               (CASE WHEN @Raw < @GoalOrder THEN @GoalOrder ELSE @Raw END) END;

SELECT StationId, Name, OrderNo,
       CAST(CASE WHEN OrderNo = @TargetOrder THEN 1 ELSE 0 END AS BIT) AS IsLanding
FROM dbo.Station
WHERE CourseId = @CourseId
  AND (@Dir = 1  AND OrderNo >  @CurrentOrder AND OrderNo <= @TargetOrder
    OR @Dir = -1 AND OrderNo <  @CurrentOrder AND OrderNo >= @TargetOrder)
ORDER BY OrderNo * @Dir;
-- 歩く順に返る。最終行が着地駅

7.4抽選候補（効果つき・既出を除外）

SELECT m.MissionId, m.Content, mem.DisplayName AS CreatedByName,
       m.EffectType, m.EffectValue, m.EffectStationId, es.Name AS EffectStationName
FROM dbo.Mission m
JOIN dbo.Member mem ON mem.MemberId = m.MemberId
LEFT JOIN dbo.Station es ON es.StationId = m.EffectStationId
WHERE m.MissionSetId = @MissionSetId
  AND m.StationId = @LandingStationId
  AND NOT EXISTS (                          -- R-14 既出の除外
      SELECT 1 FROM dbo.Turn t
      WHERE t.MissionSetId = @MissionSetId AND t.SelectedMissionId = m.MissionId);

7.5効果適用後の終了位置（DV-05）

DECLARE @EndOrder INT =
  CASE @EffectType
    WHEN 1 THEN  -- 進む（ゴール方向・ゴールでクランプ）
      CASE WHEN @Dir = 1
        THEN (CASE WHEN @LandingOrder + @EffectValue > @GoalOrder THEN @GoalOrder ELSE @LandingOrder + @EffectValue END)
        ELSE (CASE WHEN @LandingOrder - @EffectValue < @GoalOrder THEN @GoalOrder ELSE @LandingOrder - @EffectValue END) END
    WHEN 2 THEN  -- 戻る（スタート方向・スタートでクランプ）
      CASE WHEN @Dir = 1
        THEN (CASE WHEN @LandingOrder - @EffectValue < @StartOrder THEN @StartOrder ELSE @LandingOrder - @EffectValue END)
        ELSE (CASE WHEN @LandingOrder + @EffectValue > @StartOrder THEN @StartOrder ELSE @LandingOrder + @EffectValue END) END
    WHEN 4 THEN (SELECT OrderNo FROM dbo.Station WHERE StationId = @EffectStationId)
    ELSE @LandingOrder
  END;

7.6踏破率（DV-06）

SELECT
    (SELECT COUNT(*) FROM dbo.Station
      WHERE CourseId = @CourseId
        AND OrderNo BETWEEN (CASE WHEN @Dir=1 THEN @StartOrder ELSE @GoalOrder  END)
                        AND (CASE WHEN @Dir=1 THEN @GoalOrder  ELSE @StartOrder END)) AS RangeStations,
    (SELECT COUNT(DISTINCT StationId) FROM dbo.Visit
      WHERE MissionSetId = @MissionSetId)                                             AS VisitedStations;
-- DISTINCT を外すと、戻るたびに踏破率が100%を超える

操作順序備考
記録リセット（再挑戦） ① Visit（→ Photo は CASCADE） → ② Turn Visit が Turn を参照するので Visit が先。メンバー・ミッション・設定は残る
ルームごと削除 ① Visit → ② Turn → ③ Schedule（→ 出欠は CASCADE） → ④ Mission → ⑤ MissionSet.CreatedBy を NULL → ⑥ Member → ⑦ MissionSet Turn は Mission を参照するので Mission より先に消す。ver.1 から1手順増えた

MissionSet に CASCADE を張れない理由は ver.1 と同じ ── Member を経由する参照と多重カスケード経路になり、SQL Server では実行時に失敗するため。

9設計判断と根拠

ID判断根拠採らなかった案
D-01現在位置を Turn から導く 時系列で決まるので前後どちらへ動いても成立する。状態を別に持たずに済む 現在位置の列を MissionSet に持つ（更新漏れで不整合になる）
D-02手番を独立したテーブルにする 1回のサイコロで「移動・ミッション・効果」が起きるため、これらの単位が要る。進行中ターンの永続化・二重ロールの防止・既出ミッションの判定が、すべてこの1テーブルで済む Visit に出目を持たせ続ける（効果による移動を表現できない）
D-03Visit の駅一意制約を外す 戻る・ジャンプは同じ駅を必ず通り直す。再訪は正常な状態 再訪時は既存行を UPDATE する（何度訪れたかの履歴が失われる）
D-04訪問の種別を5値で持つ 始点・通り道・着地・効果移動の通り道・効果移動の到達点を区別する必要がある。「ミッションを引く駅かどうか」と「歩いた道か」が別の軸 BIT のフラグ2本（組み合わせに意味のないものが生じる）
D-05区間を駅IDで持つ（OrderNo ではなく） 路線の駅が増減しても区間の指定が壊れない StartOrderNo / GoalOrderNo を数値で持つ
D-06進む向きを列に持たない Start と Goal の前後関係から必ず決まる。持つと矛盾しうる Direction 列を追加する
D-07最大出目をルーム単位にする 同じコースでも遊び方を変えられる。コース単位だと路線ごとに固定されてしまう Course に持たせる／アプリの定数にする
D-08効果をミッションの列で持つ 効果は必ずミッションに付随し、単独では存在しない。別テーブルにすると常に結合が要る MissionEffect テーブルに分離する
D-09効果の種類を5値に絞る 進む・戻る・もう一度・ジャンプで、すごろくの動きはほぼ網羅できる。「1回休み」は、チームで1つのコマでは意味を持たないため入れていない 汎用の効果スクリプトを持たせる（過剰）
D-10効果移動先ではミッションを引かない 引くと連鎖して止まらなくなる。ジャンプ先にジャンプ効果があると無限ループになる 引けるようにして回数制限をかける（複雑）
D-11Visit にメンバー列を置かない チーム全体で1つのコマを進めるため、記録の単位はチーム メンバーごとに Visit を持つ
D-12写真の実体をDBに入れない 無料枠のストレージをすぐ消費する VARBINARY(MAX) で直接格納
