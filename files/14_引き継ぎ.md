## 3. 開発環境と、よく使うコマンド

### 前提

`Xcode`（iOS 26.4 SDK） / `xcodegen` / `dotnet`（net10.0） / `az` / `sqlcmd`。
いずれも導入済みで、`az login` と `az account`（Azure subscription 1）も通っている。

### ビルドとテスト

```bash
# ルール計算と駅マスタ（GPS・DB非依存。いちばん速い）
swift test --package-path RailAngyerCore

# API（SQLiteのインメモリDBで実際のHTTPを通す。Azureには触らない）
dotnet test RailAngyerApi.Tests

# アプリ（ユニット＋UIテスト）
xcodegen generate --spec RailAngyerApp/project.yml     # ファイルを足したら必ず実行
xcodebuild -project RailAngyerApp/RailAngyerApp.xcodeproj -scheme RailAngyerApp \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

> ⚠️ **`.xcodeproj` は `project.yml` から生成する。手で編集しない。**
> `Sources/` や `Tests/` にファイルを追加したら `xcodegen generate` を忘れると
> 「ビルドは通るのに新しいファイルが入っていない」状態になる。

### 画面を実際に見る

```bash
xcrun simctl boot "iPhone 17 Pro"
APP=$(find ~/Library/Developer/Xcode/DerivedData -name "RailAngyerApp.app" -path "*Debug-iphonesimulator*" | head -1)
xcrun simctl install booted "$APP" && xcrun simctl launch booted com.non-migi.RailAngyerApp
xcrun simctl io booted screenshot /tmp/shot.png
```

UIテストの中で撮ったスクリーンショットを取り出す場合:

```bash
xcodebuild ... -resultBundlePath /tmp/result.xcresult test
xcrun xcresulttool export attachments --path /tmp/result.xcresult --output-path /tmp/att --test-id "<テストID>"
```

### デプロイ

```bash
dotnet publish RailAngyerApi -c Release -o /tmp/publish
(cd /tmp/publish && zip -qr ../app.zip .)
az webapp deploy -g RailAngyer -n railangyer --src-path /tmp/app.zip --type zip
```

### DBに繋ぐ

```bash
# 管理者（スキーマ変更・調査）。パスワード不要
sqlcmd -S railangyer.database.windows.net -d RailAngyer --authentication-method ActiveDirectoryAzCli

# 作業場所を変えたらファイアウォールに自分のIPを足す
ip=$(curl -s ifconfig.me)
az sql server firewall-rule create -g RailAngyer -s railangyer \
  -n "mac-$(date +%Y%m%d-%H%M)" --start-ip-address $ip --end-ip-address $ip
```

## 4. 設計の芯（ここを外すと壊れる）

| 原則 | 具体 |
|---|---|
| **ローカルが正、サーバーは共有の場** | プレイは送信キューの状態に依存しない。圏外でも最後まで遊べる |
| **書き込みはすべて冪等な PUT** | 主キーはクライアント生成のUUID。再送しても二重にならない |
| **順序は時刻で決める** | 現在位置は `TurnNo` ではなく `RolledAt` の順で導く（採番衝突を実害にしない） |
| **他人のお題はAPIが伏せる** | クライアントで隠すだけでは通信を覗けば見える |
| **リクエストの `MemberId` を信用しない** | 誰がやったかは必ずトークンから引く |
| **写真の実体はAPIを通さない** | 単一Blob限定・短命のSASで端末とBlobを直結（F1の帯域を使わない） |
| **テーブルの正は `06_schema.sql`** | EF Core はその形に合わせるだけ。マイグレーションでスキーマを作らない |
| **駅マスタの正は `RailAngyerCore/Resources/*.json`** | 投入SQL（`13_courses.sql`）はJSONから生成する。手で書き写さない |

## 5. 実際に踏んだ落とし穴（同じ穴を掘らないために）

| 症状 | 原因 | 対処 |
|---|---|---|
| `POST /rooms` が 500 | `MissionSet.CreatedBy` と `Member.MissionSetId` が**循環参照**。1回の `SaveChanges` ではどちらのINSERTが先でもFK違反（547） | ルーム→メンバー→紐付けの**3段階で保存**する |
| その不具合をテストが見逃した | `CreatedBy` のFKがEFのモデルに無く、テスト用SQLiteに制約が作られていなかった。さらに**自前で開いたSQLite接続にはEFが `PRAGMA foreign_keys=ON` を送らない** | モデルにFKを追加し、`ApiFactory` でPRAGMAを送る |
| 空のお題が保存できてしまう | SwiftDataは**保存済みオブジェクトに関係を張った時点で**コンテキストに入れる。「作ってから弾く」では手遅れ | 値だけで判定する `Mission.validationError(content:...)` を関係を張る前に呼ぶ |
| App Service で設定を変えたのに読まれない | アプリケーション設定の変更で自動再起動しないことがある | `az webapp restart` を打つ |
| ローカル実行で接続文字列が読まれない | user-secrets は **Development でしか読まれない** | `DOTNET_ENVIRONMENT=Development dotnet run` |
| `az appservice plan create --sku F1 --location japaneast` が失敗 | Japan East のVM枠が0 | **Japan West** に置いた（DBはJapan Eastのまま。国内同士で往復は数ms） |
| `sqlcmd` の1回目が必ず失敗 | サーバーレスDBの自動一時停止からの復帰 | 再試行する。アプリ側も起動時に `/health` を投げて起こす |
| 日時のパースに失敗しうる | サーバーは `DATETIME2` をそのまま返すため **末尾に `Z` が付かない**ことがある | `ApiDate.parse` が両方受ける。テストは `Tests/Fixtures/*.json`（実応答）で固定 |

## 6. 途中で止まっている作業（**引き継ぎの主対象**）

利用者から出た4つの要望のうち、**1と2の土台までが入っていて、画面への反映が半分**。
現時点でビルドもテストも通る（アプリ75件通過）ので、続きから安全に始められる。

### 要望の全文

1. 地図で、写真を撮った駅がピンで分かるようにする
2. 合計時間・移動時間・ミッション時間を記録し、各場面で見られるようにする
3. 「何分/km」のペースを出す
4. 道案内は点線、実際に通ったところは実線にし、**速ければ青系・普通は緑・遅ければ赤**で色分けする

### 済んでいるもの

| 対象 | 内容 |
|---|---|
| `RailAngyerCore/Sources/RailAngyerCore/Pace.swift` | `Geo.distanceMeters`（ハーバサイン）、`Pace`（分/km・時速・表示）、`PaceCategory`（速い/ふつう/ゆっくり）、`DurationText`。**テスト7件（`PaceTests`）付き** |
| `RailAngyerApp/Sources/Game/WalkTiming.swift` | 区間ごとの記録（`Leg`）、ターンの内訳（`TurnBreakdown`：移動/ミッション/合計）、全体集計（`Total`）。**新しく保存するデータは無い**。既存の `rolledAt` / `arrivedAt` / `completedAt` から後で数え直すだけ |
| `GameSessionStore` | `timing` / `legs` / `currentTurnBreakdown` / `legs(arrivingAt:)` / `photographedOrders` を追加 |
| `BoardMapView` | **要望1・4を実装済み**。写真のある駅にカメラのピン、これから行く区間は点線、通った区間は実線でペース色分け（青/緑/赤）、凡例つき |
| `BoardView` | ヘッダーに合計・移動・ミッション時間とペースを追加（**未確認：シミュレータでの見た目チェックがまだ**） |

**速さの区切り**は `PaceCategory` に定義してある。10分/km未満=速い、10〜14=ふつう、14超=ゆっくり
（徒歩の平均は約12分/km）。駅間の**直線距離**で測るので、実際のペースよりやや遅め（数字が大きめ）に出る。

### 残っている手順

1. **`WalkTiming` のテストを書く**（いちばん先にやる）
   - 置き場所: `RailAngyerApp/Tests/WalkTimingTests.swift`
   - 参考になる書き方: `JourneySummaryTests.swift`（`playTurn` で1ターン歩かせるヘルパーがある）
   - 確かめたいこと: 通り道をまたぐ区間の分割 / 着地〜ターン完了が「ミッション時間」になること /
     効果による移動が「移動時間」に入ること / 進行中のターンでも「いままで」で出ること /
     時刻が前後した記録を数えないこと
2. **駅詳細（`StationDetailView`）に区間の記録を出す** — `store.legs(arrivingAt: order)` を使い、
   訪問ごとに「前の駅から何分・何分/km」を出す
3. **ふりかえり（`JourneySummaryView` / `JourneySummary`）に内訳を足す** —
   いまは `elapsed` だけ。`WalkTiming.total` の移動/ミッション/その他の内訳と平均ペースを出す。
   共有画像（`SummaryCard`）にも同じ数字を入れる
4. **ターン中の画面（`TurnFlowView`）に「今回の移動時間・ペース」を出す** —
   `store.currentTurnBreakdown` を使う。歩いている最中にいちばん見たい数字
5. **シミュレータで見た目を確認する**（§3のコマンド）。特に地図の凡例が
   ボタンや現在地表示と重なっていないか
6. **ドキュメントを更新する** — `10_アプリ設計.md` に時間集計の節を足し、
   `04_ロードマップ.md` と `README.md` のテスト件数を直す

> ⚠️ **色だけに頼らせない。** 地図の色分けは凡例と数字（分/km）を必ず併記する。
> 色覚特性によっては青と緑の区別がつきにくい。

## 8. 秘密情報の扱い

- **接続文字列・キーはリポジトリに置かない。** ローカルは user-secrets、App Service はアプリケーション設定
- `railangyer_app` のパスワードは macOS キーチェーン
  （`security find-generic-password -a railangyer_app -s RailAngyer -w`）
- ストレージのアカウントキーは会話の中で共有された経緯がある。
  気になる場合は `az storage account keys renew -n railangyer -g RailAngyer --key key1` で失効できる
  （失効したら App Service の `ConnectionStrings__Storage` と user-secrets の両方を貼り替える）

## 9. 進め方の約束ごと（この作業で守ってきたこと）

- **個人開発なので `main` に直接コミットする。** ブランチは切らない
- コミットメッセージは日本語。**何をしたかより、なぜそうしたかを書く**
- 実装したら**必ずテストを足し、全スイートを流してからコミットする**
- ドキュメント（`files/`）はコードと同じコミットで直す。**実態とズレた記述を残さない**
- 「動いた」と言う前に、実際に流した結果を確認する。
  API は実物のAzureに対しても1往復させて確かめてきた（確認用に作ったデータは毎回消している）
