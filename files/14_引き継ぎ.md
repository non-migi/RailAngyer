## 3. 開発環境と、よく使うコマンド

### 前提

`Xcode`（iOS 26.5 SDK） / `xcodegen` / `dotnet`（net10.0） / `az` / `sqlcmd`。
いずれも導入済みで、`az login` と `az account`（Azure subscription 1）も通っている。

### ビルドとテスト

```bash
# ルール計算と駅マスタ（GPS・DB非依存。いちばん速い）
swift test --package-path RailAngyerCore

# API（SQLiteのインメモリDBで実際のHTTPを通す。Azureには触らない）
dotnet test RailAngyerApi.Tests

# アプリ（ユニット＋UIテスト）
xcodegen generate --spec RailAngyerApp/project.yml     # ファイルを足したら必ず実行
tools/prepare-simulator.sh "iPhone 17 Pro"             # 位置情報を許可（新しい環境では必須）
xcodebuild -project RailAngyerApp/RailAngyerApp.xcodeproj -scheme RailAngyerApp \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

> ⚠️ **UIテストの前に `tools/prepare-simulator.sh` を打つ。**
> 飛ばすと位置情報の許可ダイアログが操作を塞ぎ、
> `ArrivalUITests` の自動到着（`testWalkingIntoRadiusTriggersArrival`）だけが落ちる。
> **アプリの不具合ではない。** 手動到着のテストは通るので、片方だけ落ちたらまずこれを疑う。

> ⚠️ **`.xcodeproj` は `project.yml` から生成する。手で編集しない。**
> `Sources/` や `Tests/` にファイルを追加したら `xcodegen generate` を忘れると
> 「ビルドは通るのに新しいファイルが入っていない」状態になる。

### 画面を実際に見る

```bash
xcrun simctl boot "iPhone 17 Pro"
APP=$(find ~/Library/Developer/Xcode/DerivedData -name "RailAngyerApp.app" -path "*Debug-iphonesimulator*" | head -1)
xcrun simctl install booted "$APP" && xcrun simctl launch booted com.non-migi.RailAngyerApp
xcrun simctl io booted screenshot /tmp/shot.png
```

UIテストの中で撮ったスクリーンショットを取り出す場合:

```bash
xcodebuild ... -resultBundlePath /tmp/result.xcresult test
xcrun xcresulttool export attachments --path /tmp/result.xcresult --output-path /tmp/att --test-id "<テストID>"
```

### デプロイ

```bash
dotnet publish RailAngyerApi -c Release -o /tmp/publish
(cd /tmp/publish && zip -qr ../app.zip .)
az webapp deploy -g RailAngyer -n railangyer --src-path /tmp/app.zip --type zip
```

### DBに繋ぐ

```bash
# 管理者（スキーマ変更・調査）。パスワード不要
sqlcmd -S railangyer.database.windows.net -d RailAngyer --authentication-method ActiveDirectoryAzCli

# 作業場所を変えたらファイアウォールに自分のIPを足す
ip=$(curl -s ifconfig.me)
az sql server firewall-rule create -g RailAngyer -s railangyer \
  -n "mac-$(date +%Y%m%d-%H%M)" --start-ip-address $ip --end-ip-address $ip
```

## 4. 設計の芯（ここを外すと壊れる）

| 原則 | 具体 |
|---|---|
| **ローカルが正、サーバーは共有の場** | プレイは送信キューの状態に依存しない。圏外でも最後まで遊べる |
| **書き込みはすべて冪等な PUT** | 主キーはクライアント生成のUUID。再送しても二重にならない |
| **順序は時刻で決める** | 現在位置は `TurnNo` ではなく `RolledAt` の順で導く（採番衝突を実害にしない） |
| **他人のお題はAPIが伏せる** | クライアントで隠すだけでは通信を覗けば見える |
| **リクエストの `MemberId` を信用しない** | 誰がやったかは必ずトークンから引く |
| **写真の実体はAPIを通さない** | 単一Blob限定・短命のSASで端末とBlobを直結（F1の帯域を使わない） |
| **テーブルの正は `06_schema.sql`** | EF Core はその形に合わせるだけ。マイグレーションでスキーマを作らない |
| **駅マスタの正は `RailAngyerCore/Resources/*.json`** | 投入SQL（`13_courses.sql`）はJSONから生成する。手で書き写さない |

## 5. 実際に踏んだ落とし穴（同じ穴を掘らないために）

| 症状 | 原因 | 対処 |
|---|---|---|
| `POST /rooms` が 500 | `MissionSet.CreatedBy` と `Member.MissionSetId` が**循環参照**。1回の `SaveChanges` ではどちらのINSERTが先でもFK違反（547） | ルーム→メンバー→紐付けの**3段階で保存**する |
| その不具合をテストが見逃した | `CreatedBy` のFKがEFのモデルに無く、テスト用SQLiteに制約が作られていなかった。さらに**自前で開いたSQLite接続にはEFが `PRAGMA foreign_keys=ON` を送らない** | モデルにFKを追加し、`ApiFactory` でPRAGMAを送る |
| 空のお題が保存できてしまう | SwiftDataは**保存済みオブジェクトに関係を張った時点で**コンテキストに入れる。「作ってから弾く」では手遅れ | 値だけで判定する `Mission.validationError(content:...)` を関係を張る前に呼ぶ |
| App Service で設定を変えたのに読まれない | アプリケーション設定の変更で自動再起動しないことがある | `az webapp restart` を打つ |
| ローカル実行で接続文字列が読まれない | user-secrets は **Development でしか読まれない** | `DOTNET_ENVIRONMENT=Development dotnet run` |
| `az appservice plan create --sku F1 --location japaneast` が失敗 | Japan East のVM枠が0 | **Japan West** に置いた（DBはJapan Eastのまま。国内同士で往復は数ms） |
| `sqlcmd` の1回目が必ず失敗 | サーバーレスDBの自動一時停止からの復帰 | 再試行する。アプリ側も起動時に `/health` を投げて起こす |
| **起動直後に落ちる**（`EXC_BREAKPOINT` / `_InvalidFutureBackingData`） | 消したお題を `Turn.selectedMission` が掴んだまま残り、`selectedMission?.id` を読んだ瞬間に落ちる。**SwiftData は消えた行の属性を読むと fatalError で止まる**（catch できない） | 消す前に参照を外す。読むときは属性ではなく `persistentModelID` で突き合わせる。起動時に `repairDanglingReferences()` で古い参照を掃除する |
| 日時のパースに失敗しうる | サーバーは `DATETIME2` をそのまま返すため **末尾に `Z` が付かない**ことがある | `ApiDate.parse` が両方受ける。テストは `Tests/Fixtures/*.json`（実応答）で固定 |
| **UIテストの自動到着だけが落ちる**（`半径に入っても到着にならない`） | シミュレータに位置情報の許可が無く、ダイアログが操作を塞ぐ。手動到着のテストは通るので不具合に見える | `tools/prepare-simulator.sh` を**先に**打つ。ダイアログをテスト内で閉じる方法は取りこぼしがあったため、事前付与の方式にしてある |
| 許可を付与したのに、まだ自動到着だけが落ちる | `simctl privacy grant` の **`location-always` だけでは足りない**。消したばかりのシミュレータでは測位が始まらない。アプリは使用中→常に許可の2段で求めるため、1段目の `location` が要る | **両方を付与する。** `prepare-simulator.sh` は2つ打つようにしてある |
| UIテストが軒並み `Test crashed with signal kill` / `Restarting after unexpected exit` になる | 同じシミュレータで重い実行を何度も続けると詰まる（地図を描く画面が多い）。**アプリは落ちていない**（手で起動すれば動く） | `xcrun simctl shutdown` → `erase` → `boot` → `prepare-simulator.sh` で作り直す。落ちた顔ぶれを**変更前のコミットでも**流して、同じなら環境side |
| **UIテストが単独では通るのに、まとめて流すと落ちる**（`手動到着のボタンが見つからない`） | シミュレータの現在地は**テストをまたいで残る**。位置を動かすテストの後に走ると、出発した瞬間に目的地の圏内にいて自動到着し、手動到着のボタンが消える | 手動到着を使うテストは `setUp` で現在地を麻生に戻す（`ResetJourneyUITests` / `TimingUITests`） |
| コースを1本足したら、関係のないテストが落ちた | 同梱コースの**名前と本数をテストに書き写していた**（`ModelsTests` / `CourseSelectionTests`） | 数と名前は `StationMaster.all()` から引いて突き合わせる。書き写しは必ず腐る |
| 駅間が4kmを超える路線を弾いてしまった | 駅間の上限を市街地の地下鉄に合わせて4kmにしていた | 郊外の路線には長い駅間が実在する（阪急京都本線 高槻市〜上牧 約4.3km）。上限は徒歩1時間ぶん＝5kmに緩めた |
| **予定を保存した直後に落ちる**（`EXC_BAD_ACCESS` / `SwiftData.DefaultStore.FutureCache.pruneValues` / 落ちたのは**メインスレッドではない**） | `SyncService` に `@MainActor` が無く、`await` のたびに別スレッドへ移っていた。取り込みの `ModelContext.save()` が、画面側の読み出しと同時に走って壊れる。**SwiftData のコンテキストはスレッドをまたげない** | `SyncService` / `GameSessionStore` / `SyncQueue` を `@MainActor` にする。**外さない。** 通信は `URLSession` が別スレッドで行うので、待っている間に画面は止まらない |
| その不具合が長く見つからなかった | 競合なので**運が良ければ通ってしまう**。しかも `pullSchedules` にテストが1件も無かった | 取り込みは中身のテストを必ず置く（`SyncServiceTests` の「予定の取り込み」5件）。**落ちたスタックの一番上がアプリの外（SwiftData / libswiftCore）なら、まずスレッドを疑う** |
| **予定が立てられない**（保存が押せる状態にならない） | 地図（170pt）を先に挟んだせいで、**名前の入力欄が画面の外へ出た**（y=855 / 画面高874）。保存は名前が空だと押せないので、押せない理由が見えない | 新規の予定は**名前を最初から入れる**（「南北線を歩く」）。名前のセクションを地図より前に置く。空のときは赤字で理由を出す。**入力より下に飾りを置かない** |
| **コースの行を押しても何も起きない** | `LabeledContent` を `Button` に入れて `.buttonStyle(.plain)` を付けたら、タップがボタンに届かなくなった。**アクセシビリティ上は `hittable: true`** なので、テストからは押せているように見える | 行は素の `HStack` ＋ `.contentShape(Rectangle())` にする。**`app.debugDescription` を撮って、押した後に画面が変わったかで判断する** |
| **路線を選んでも入力画面へ戻らない** | 3段たどった先で `dismiss()` を呼んでも、`NavigationLink` で押し込んだ画面までは戻らない。選んだあとピッカーの中に取り残される | コース選択は**独立したシート**にし、自前の `NavigationStack` を持たせる。何段たどっていても `dismiss()` ひとつで確実に閉じる |
| お題を「いつでも見える」にしたら、他人のお題が全部自分の作ったものになった | 取り込みで `mission.member` に一律 `me` を入れていた。伏せる設定では自分のぶんしか返らないので、それで足りていた | **書き手（`createdByName`）で突き合わせる。** 見え方を変えると返る顔ぶれが変わることを忘れない |
| お楽しみへ戻したのに、他人のお題が見えたまま | サーバーは返さなくなるが、**端末に取り込んだぶんは残る** | 戻したときに、自分以外が書いたお題を端末から消す（`updateMissionVisibility`） |
| **日付が「Aug 2, 2026 at 9:00」と英語で出る** | `DEVELOPMENT_LANGUAGE` が既定の `en` のままで、**アプリが英語のアプリとして名乗っていた**。端末が日本語でも `Date.formatted()` はアプリの言語に従う | `project.yml` で `DEVELOPMENT_LANGUAGE: ja` と `CFBundleLocalizations: [ja]` を宣言する。**画面ごとに `.environment(\.locale)` を貼って回らない** |
| サイコロが斜めのまま止まって見える | 静止姿勢に z（横倒し）を 0.05 入れていた。立体に見せるつもりが「まだ転がり切っていない」と読める | **z は 0 にする。** 傾けるなら x/y だけ、それも浅く |
| お題を書く画面に、区間の外の駅まで出ていた | ホームから開いたとき（予定を渡さないとき）に**コースの全駅**を並べていた | 予定が無いときは `store.stationsInOrder`（＝いま遊んでいる区間）を使う。区間外の駅に書いても永久に引かれない |
| `xcodebuild -exportArchive` が `error: exportArchive Failed to Use Accounts` で落ちる | Xcode に入れた Apple ID のセッションが切れた。**アーカイブは通るのに送信だけ落ちる**ので、ビルドの不具合に見える | サインインし直さなくてよい。`-authenticationKeyPath` / `-authenticationKeyID` / `-authenticationKeyIssuerID` に**クラッシュ報告と同じ鍵**を渡す（`15_TestFlight準備.md` §5） |
| **一周の予定で、お題を書く画面に地図が出ない**（札幌市電） | 一周は**スタートとゴールが同じ駅**。それを範囲として扱うと `1...1` になり、駅が1つしか取れない。地図は2駅以上でしか出ない | `isLap` を見て、**一周ならコース全体**を返す。予定の一覧・共有・お題の3か所とも同じ罠がある。**一周を足したら、区間を範囲で絞っている場所を全部見直す** |
| 地図に出したお題の文字が読めない | 縮尺に関わらず**全駅に出していた**。路線全体が入る画面では16〜30個の吹き出しが、駅名とも経路の線とも重なる | **寄ったときだけ出す**（緯度0.02度＝約2.2kmより狭いとき）。`onMapCameraChange` で判断する。色で塗らず下地を透かすと線の上でも読める |
| 盤面へ戻ったとき、戻り口が「サイコロを振る」に被った | 戻り口を `overlay` で**浮かせて重ねた**。しかも進行中のサイコロは押しても何も起きない飾りだった | 重ねない。**盤面の操作そのものを差し替える**（進行中は「◯◯へ歩く」に変える） |
| 山手線の「東京スタート・東京ゴール」が**予定では作れない** | 予定の保存が `startOrder == goalOrder` を一律に弾いていた。ルール設定には「一周する」があるのに、予定には無かった | `Schedule.isLap` を持たせ、**環状線のときだけ**同じ駅を許す。まわる向きも予定に持たせて、始めるときに移す |
| 歩いている間ずっと全体マップが見えない | `TurnFlowView` を `isPresented: .constant(...)` で出しており、**閉じる手段が無かった**。次の駅しか見えず「あとどれくらいか」が分からない | 画面の上に「次の駅／全体マップ」の切り替えを置き、右上から盤面へ抜けられるようにした。抜けている間は戻る口を盤面に出し、次に振ったら自動で前に出す |
| **UIテスト10件のうち8件が `Test crashed with signal kill.` で落ちる**（アサーション失敗ではない。アプリのクラッシュログも残らない） | 画面を持たないセッション（バックグラウンド実行）でUIテストを流すと、テストランナー側がSIGKILLされる。**`main` の状態でも同じ8件が同じ理由で落ちる**ので、コードの退行ではない | 切り分けは**変更前のコミットで同じUIテストを流して比べる**のが確実（同じ顔ぶれが落ちれば環境）。UIテストは対話セッションで流す。ユニットテストは影響を受けない |

## 6. 写真・時間・ペースの追加要望（完了）

利用者から出た次の4要望は、集計・画面反映・テスト・シミュレータ確認まで完了した。

### 要望の全文

1. 地図で、写真を撮った駅がピンで分かるようにする
2. 合計時間・移動時間・ミッション時間を記録し、各場面で見られるようにする
3. 「何分/km」のペースを出す
4. 道案内は点線、実際に通ったところは実線にし、**速ければ青系・普通は緑・遅ければ赤**で色分けする

### 実装したもの

| 対象 | 内容 |
|---|---|
| `RailAngyerCore/Sources/RailAngyerCore/Pace.swift` | `Geo.distanceMeters`（ハーバサイン）、`Pace`（分/km・時速・表示）、`PaceCategory`（速い/ふつう/ゆっくり）、`DurationText`。**テスト7件（`PaceTests`）付き** |
| `RailAngyerApp/Sources/Game/WalkTiming.swift` | 区間ごとの記録（`Leg`）、ターンの内訳（`TurnBreakdown`：移動/ミッション/合計）、全体集計（`Total`）。**新しく保存するデータは無い**。既存の `rolledAt` / `arrivedAt` / `completedAt` から後で数え直す |
| `GameSessionStore` | `timing` / `legs` / `currentTurnBreakdown` / `legs(arrivingAt:)` / `photographedOrders` を追加 |
| `BoardMapView` / `BoardView` | 写真駅にカメラのピン、未通過は点線、通過済みは実線でペース色分け（青/緑/赤）。凡例と全体時間・平均ペースつき |
| `StationDetailView` | 訪問ごとに前の駅、区間時間、分/km、効果移動かを表示 |
| `TurnFlowView` | 今回の合計・移動時間とペースを1秒ごとに更新 |
| `JourneySummary` / `JourneySummaryView` | 合計・移動・ミッション・その他と平均ペースを表示。共有画像にも同じカードを使用 |
| `WalkTimingTests` | 区間分割、ミッション時間、効果移動、進行中、時刻不整合の5件 |
| `TimingUITests` | 1ターンを通して盤面・駅詳細・ふりかえりを検証し、3画面のスクリーンショットを保存 |

**速さの区切り**は `PaceCategory` に定義してある。10分/km未満=速い、10〜14=ふつう、14超=ゆっくり
（徒歩の平均は約12分/km）。駅間の**直線距離**で測るので、実際のペースよりやや遅め（数字が大きめ）に出る。

シミュレータでは、地図の凡例が下部ボタンと重ならず、駅詳細とふりかえりの値も
欠けずに収まることを確認済み。色だけに頼らず、凡例と分/kmを併記している。

## 9. 歩いた跡・地図の作り込み・写真（完了）

| 対象 | 内容 |
|---|---|
| `TrackPoint`（モデル） | 歩いている間のGPSを間引いて残す。**サーバーへは送らない**（生の座標を端末外に出さない約束） |
| `RailAngyerCore/TrackSegments.swift` | 跡を**50mごとに刻んで**区切りごとの速さを出す。テスト11件 |
| `CourseRouteProvider` | これから歩く線を**道路沿い**にする。手前の区間から少しずつ、取れなければ直線のまま |
| `JourneyTrackMapView` | ふりかえりの全体地図。跡・通った駅・撮った写真を1枚に |
| `PhotoGalleryView` / `PhotoViewerView` | 撮った写真をまとめて見る。ホーム・ふりかえり・写真の帯から開ける |
| `JourneySummary.walkedMeters` | 歩いた距離。**跡があれば実測、無ければ駅を結んだ目安**。どちらかを画面に明示する |

**決めたこと（外すと作り直しになる）**

- **跡はサーバーへ送らない。** プライバシーポリシー §1 で約束している。
  共有するのは「到着した駅と時刻」だけ
- **跡は歩いている間だけ残す。** 待っている間まで拾うと、駅で立ち止まった点が団子になる。
  精度が60mより粗い点も混ぜない（地下や谷間で街を横切る線になる）
- **色は距離で刻む（時間ではない）。** 地図の上で等しい長さにならないと、
  止まっている間だけ濃くなり、速いところほど色が大雑把になる。
  止まっていた区切りは色に使わない
- **刻み幅（50m）と点の間隔（10m）は組で決まる。** 片方だけ変えると、
  1区切りに2点しか入らずGPSの誤差がそのまま色に出る
- **道路沿いの経路は「取れたら使う」。** MapKit は続けて投げると絞られるので、
  一度に取るのは手前の数区間だけ。取れなくても直線で描いて進行を止めない

## 11. 秘密情報の扱い

- **接続文字列・キーはリポジトリに置かない。** ローカルは user-secrets、App Service はアプリケーション設定
- `railangyer_app` のパスワードは macOS キーチェーン
  （`security find-generic-password -a railangyer_app -s RailAngyer -w`）
- ストレージのアカウントキーは会話の中で共有された経緯がある。
  気になる場合は `az storage account keys renew -n railangyer -g RailAngyer --key key1` で失効できる
  （失効したら App Service の `ConnectionStrings__Storage` と user-secrets の両方を貼り替える）

## 12. 進め方の約束ごと（この作業で守ってきたこと）
